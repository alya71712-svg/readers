# مشاركة مقاطع القراءة مع خدمات البحث العلمي والذكاء الاصطناعي

## ما تعنيه النتائج للقارئ

يفحص هذا التقرير **مجموعة منتقاة من أبرز الخدمات التي جرى التحقق منها**، لا جميع أدوات السوق بلا استثناء. والخلاصة العملية لقارئ الكتب هي: **لا يوجد في المصادر الرسمية التي فُحصت دليل عام على رابط عميق يملأ الاستعلام مسبقاً لجميع الخدمات**. لذلك فالخيار الملائم حالياً هو نسخ حزمة منظمة إلى الحافظة، وفتح الخدمة المقصودة، ثم ترك المستخدم يلصقها بنفسه؛ لا إرسال النص تلقائياً ولا افتراض أن فتح الموقع ينقل محتوى الحافظة إليه.

تضم واجهة القارئ الحالية الحزمة المنسوخة: اسم الكتاب، والمؤلف، ورقم الفقرة، والنص، وملاحظة أو تظليل ذي صلة، وتصوغ طلباً أكاديمياً بالعربية أو الإنجليزية وفق لغة النص. هذه الحزمة **سياق ينسخه المستخدم**، وليست مستنداً أرسلته الواجهة إلى خدمة خارجية. ينبغي كذلك اختيار فعل يناسب نوع الخدمة: البحث عن أدلة، أو اكتشاف مراجع انطلاقاً من ورقة، أو إضافة مقتطف إلى دفتر مصادر، أو تلخيص نص.

## الفئات وما تعنيه للقارئ

- **سؤال أدبيات أو أدلة:** Consensus وElicit وScite وSciSpace وUndermind وPerplexity. يمكن صياغة طلب بحث مستند إلى الفكرة في المقتطف، لكن قبول سؤال نصي لا يعني أن الخدمة استوردت المقتطف كمصدر أو حللته كوثيقة.
- **استكشاف شبكة مراجع:** ResearchRabbit وLitmaps وConnected Papers. نقطة الانطلاق المعتادة ورقة معروفة أو عنوان أو DOI أو مجموعة مراجع؛ هذه الخدمات تتبع صلات الأوراق ولا تجيب بالضرورة عن سؤال المقتطف.
- **محركات أو فهارس أوراق:** Semantic Scholar وOpenAlex. الأولى تتيح البحث عن الدراسات وبعض وظائف السؤال على ورقة مدعومة؛ أما OpenAlex فهو فهرس/رسم معرفي وواجهة API، **وليس مساعداً توليدياً**.
- **دفتر مصادر أو إدخال مستندات للتلخيص:** NotebookLM وScholarcy. الأول يتيح إضافة النص إلى دفتر ثم محاورته؛ والثاني يستورد نصاً أو مستنداً وينتج ملخصات منظمة، ولا ينبغي وصفه كمساعد محادثة عام ما لم توثق الخدمة ذلك.

## تفاصيل الخدمات

### سؤال الأدبيات والأدلة

- **Consensus** — يقبل البحث أسئلة بلغة طبيعية وكلمات مفتاحية، ويعرض دراسات وإجابات مسندة بالأدلة؛ كما يوثق رفع PDF وسؤالاً عن المستند. للقارئ: افتح صفحة البحث والصق الحزمة يدوياً مع سؤال مثل «ما الأدلة العلمية ذات الصلة بهذه الفكرة؟». لا تعتبر النص الملصوق ملفاً أو دليلاً مستقلاً، ولا تعتمد على URL لتعبئة البحث تلقائياً. [1] [2]
- **Elicit** — وكيل البحث يستقبل سؤالاً وسياقاً، ويمكنه التعامل مع ملفات يرفعها المستخدم، فيما توجد واجهات API منفصلة للبحث والتقارير/الوكيل. للقارئ: الصق الحزمة يدوياً بوصفها سياقاً لسؤال بحثي محدد. الـAPI مسار تطوير مستقل، متاح وفق النتائج على خطط Pro فما فوق ويتطلب مفتاحاً؛ لا يوجد دليل هنا على رابط للموقع يملأ السؤال مسبقاً. [3] [4]
- **Scite** — يجيب المساعد عن أسئلة في سياق الأدبيات ويعرض سياق الاستشهادات الداعمة أو المتعارضة. من الحالات القليلة التي توثق فيها الخدمة مساراً مباشراً من المتصفح: تحديد عبارة في صفحة واختيار Ask scite.ai Assistant من قائمة الإضافة. إذا تعذر ذلك في قارئ الكتب، انسخ الحزمة وافتح المساعد للصقها يدوياً. واجهة API مسار منفصل يتطلب صلاحية ومصادقة، وقد لا تكون صلاحية المساعد متاحة افتراضياً. [5] [6] [7]
- **SciSpace** — يجمع البحث عن الأوراق مع ميزة Chat with PDF التي تتطلب رفع PDF أو اختياره ثم طرح سؤال عنه؛ توثيق البحث يخص اكتشاف الأدبيات ولا يثبت ملء المحادثة عبر رابط. للقارئ: للصياغة أو التلخيص، يمكن لصق النص يدوياً في محرر AI Writer؛ أما إجابة مرتبطة بمصدر فتتطلب إدخال/فتح PDF داخل الخدمة. لا تعرض محرر النص كأنه محادثة بحثية موثقة، ولا تفترض توافر API عام لإرسال مقتطف القارئ. [8] [9]
- **Undermind** — بحث عميق ينطلق من هدف أو سؤال بحثي، ويمكنه العمل مع أوراق ومساحة عمل وملفات PDF بحسب الأدوات الموثقة. للقارئ: افتح التطبيق ودع المستخدم يلصق الحزمة مع طلب مثل «ابحث عن الأدبيات التي تؤيد أو تناقض هذا الادعاء». التوثيق البرمجي المتاح هو MCP بتفويض المستخدم، وليس دليلاً على رابط عميق أو API عامة لتمرير محتوى القارئ. [16]
- **Perplexity** — يتيح سؤالاً نصياً وبحثاً في الويب ومصادر أكاديمية، كما يدعم إرفاق ملفات في واجهة الويب. للقارئ: افتح الموقع فقط، ثم الصق الحزمة وأضف توجيهاً واضحاً للتحقق من الفكرة بمصادر موثوقة. ملفات الواجهة وواجهة Agent API مساران مختلفان؛ لا تفترض أن API تقبل المرفقات أو أن URL يفتح جلسة جاهزة. [23] [24]

### استكشاف شبكة المراجع

- **ResearchRabbit** — يكتشف أوراقاً ذات صلة انطلاقاً من كلمات مفتاحية أو عنوان أو DOI أو أوراق بذرة، ويعرض الروابط بينها؛ ليس موثقاً كمساعد محادثة لتحليل فقرة حرة. للقارئ: انسخ العنوان أو DOI إن كان معروفاً، وافتح الخدمة ليختاره المستخدم؛ يمكن استيراد مراجع BibTeX أو استخدام Zotero. لا ترسل المقتطف على أنه بذرة ورقة. [12] [13]
- **Litmaps** — ينشئ خرائط أوراق من موضوعات وأوراق بداية، ويستكشف علاقات الاستشهاد والتشابه النصي في عناوين وملخصات الأوراق. للقارئ: افتح الخدمة وابحث يدوياً عن عنوان/DOI ثم اختر الورقة لاستكشاف الأوراق المرتبطة. الاستيراد الموثق يخص سجلات المراجع لا التظليلات؛ لا يوجد ما يثبت تمرير فقرة عبر رابط. [14] [15]
- **Connected Papers** — يبني رسماً بصرياً لأوراق مشابهة انطلاقاً من ورقة، اعتماداً على التشابه الببليوغرافي/الاستشهادات؛ ليس مساعداً عاماً يجيب عن سؤال أو يقرأ كتاباً. للقارئ: اطلب من المستخدم اختيار ورقة مناسبة أو إدخال DOI معروف. لا تعامل النص الحر كمصدر رسم، ولا كإجابة عن المقتطف. [21] [22]

### محركات وفهارس أوراق

- **Semantic Scholar** — محرك بحث أوراق مع ملخصات ووظائف لقارئ أوراق؛ تتيح Ask This Paper سؤالاً عن ورقة بعينها عندما تكون الميزة متاحة، ولا تثبت الوثائق إدخال مقتطف خارجي إليها. للقارئ: انسخ الحزمة ثم الصقها يدوياً في البحث لاستكشاف الأوراق؛ وللسؤال عن الورقة الأصلية، افتح صفحة تلك الورقة واستخدم الميزة عند توفرها. تشير النتائج إلى أن إتاحة السؤال محدودة لبعض الأوراق واختُبرت للأوراق الإنجليزية. [10] [11]
- **OpenAlex** — فهرس مفتوح للأبحاث مع بحث API، بما في ذلك البحث الدلالي بنص/وصف؛ نتائج البحث هي سجلات أوراق، وليست إجابة مولّدة عن النص. للقارئ، إذا أُريد تكامل مطور منفصل، يمكن إرسال مقتطف مختصر كاستعلام دلالي عبر API وفق وثائقها؛ وإلا فافتح الموقع ودع المستخدم يلصق النص يدوياً. لا تصف ذلك بأنه رفع للفقرة أو تحليل لها كمستند. [27] [28]

### دفتر مصادر أو تلخيص مستندات

- **Google NotebookLM (Gemini Notebook)** — يعتمد على مصادر يضيفها المستخدم ثم يجيب عن أسئلة مرتبطة بها مع إحالات. للقارئ: افتح دفتراً مناسباً، وأضف المقتطف يدوياً كمصدر/ملاحظة، ثم اطرح السؤال في الدفتر. واجهة API الموثقة لمنتج Enterprise مسار منفصل، ولا تثبت وجود API دردشة أو رابط يملأ واجهة المستهلك. [17] [18]
- **Scholarcy** — يستورد مستندات ونصاً عادياً ويحولها إلى ملخصات وبطاقات منظمة. للقارئ: افتح المكتبة، ثم استخدم الاستيراد ولصق النص العادي يدوياً؛ الحد الموثق للنص الملصوق 5,000 حرف، لذا قسّم النص الأطول. لم يظهر في المصادر المراجعة توثيق لواجهة سؤال حر أو رابط يملأ الاستيراد تلقائياً. [25] [26]

### خدمة خارج النطاق النصي

- **SciBase** — ليست منصة بحث أدبيات أو تحليل نصوص؛ إنها شركة تقنية طبية تطور أجهزة Nevisense لقياسات الجلد باستخدام تقنية EIS وتطبيقاتها التشخيصية/البحثية. لا يوجد في المصادر التي فُحصت دليل على حقل لإدخال مقتطف أو سؤال نصي. ربما كان المقصود في سياق القارئ SciSpace، لكن لا يمكن الجزم بذلك أو بافتراض وقوع خطأ؛ الأفضل إبقاء الاسمين منفصلين وشرح اختلاف الغرض. [19] [20]

## التوصية العملية للقارئ

اعتمد افتراضياً زراً واحداً واضحاً مثل **«نسخ السياق وفتح الخدمة»**، لا «إرسال إلى الخدمة». عند تفعيله:

1. انسخ حزمة منظمة إلى الحافظة: اسم الكتاب، المؤلف، رقم الفقرة، النص المحدد، وأي ملاحظة/تظليل ذي صلة.
2. كوّن سؤالاً أكاديمياً موجزاً بالعربية أو الإنجليزية بحسب لغة النص، مع بيان المطلوب: العثور على أدلة، تفسير، تلخيص، أو اكتشاف مراجع.
3. افتح الصفحة العامة المناسبة من دون وضع المقتطف أو السؤال في عنوان URL، ثم اشرح للمستخدم أن عليه اللصق يدوياً. عند الخدمة القائمة على ورقة بذرة، فضّل العنوان أو DOI؛ وعند خدمة الدفتر/التلخيص، وجّه المستخدم لإضافة المقتطف كمصدر/نص مستورد.
4. لا تساوِ بين «بحث عن أوراق حول الفكرة» و«تحليل النص نفسه». إذا لم توثق الخدمة استقبال PDF أو نص كمصدر، صف الإدخال بأنه سؤال/كلمات بحث فقط.

توفر بعض الخدمات APIs موثقة، ومنها Elicit وConsensus وScite وOpenAlex، لكنها **مسارات تكامل منفصلة** وقد تتطلب مفاتيح أو خططاً أو صلاحيات خاصة. لا يعني وجود API أن تطبيق القارئ الحالي يستخدمها، ولا ينبغي تضمين أسرار أو مفاتيح API في الواجهة. أي إرسال آلي لاحق يحتاج تكاملاً خادمياً مستقلاً، والتحقق من شروط الخدمة والصلاحيات، وموافقة واضحة من المستخدم قبل نقل النص.
